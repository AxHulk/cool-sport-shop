

## Ускорение загрузки: план оптимизации

### Текущая ситуация

- **3D модели: 322 МБ** (от 2.8 до 45 МБ каждая) — загружаются по умолчанию на странице товара
- **Фото: 92 МБ** (до 2.9 МБ на файл, не оптимизированы)
- Все изображения импортируются статически в `products.ts` — весь бандл тяжёлый
- 3D-вьюер (Three.js) загружается сразу при открытии страницы товара

### Что сделаем

#### 1. Фото по умолчанию, 3D — по кнопке (ваше предложение)
Переключим `view3D` с `true` на `false` в `ProductPage.tsx`. 3D-модель (10–45 МБ) загрузится только когда пользователь нажмёт кнопку "3D". Это мгновенно ускорит открытие страницы товара.

#### 2. Ленивая загрузка 3D-вьюера (lazy import)
Компонент `ProductViewer3D` (Three.js, ~500 КБ JS) будет загружаться через `React.lazy()` только при нажатии на кнопку "3D". Сейчас он тянется в бандл сразу.

#### 3. Оптимизация изображений
- Конвертировать все `.png` и `.jpg` в **WebP** (экономия 40–60% размера)
- Добавить `loading="lazy"` и `decoding="async"` на все изображения в карточках и на странице товара
- Уменьшить разрешение крупных фото (>2 МБ) до разумных размеров (1200px по длинной стороне)

#### 4. Skeleton-загрузка для изображений
Показывать анимированный placeholder пока фото грузится — страница будет выглядеть быстрее.

### Приоритеты

| Шаг | Эффект | Сложность |
|-----|--------|-----------|
| 1. Фото по умолчанию | Огромный — убираем 10-45 МБ при загрузке | Минимальная |
| 2. Lazy-загрузка Three.js | Большой — убираем ~500 КБ JS из бандла | Низкая |
| 3. WebP + ресайз | Средний — экономия 30-50 МБ суммарно | Средняя |
| 4. Skeleton | Визуальный — воспринимаемая скорость | Низкая |

### Технические детали

- `ProductPage.tsx`: `useState(false)` вместо `useState(true)` для `view3D`
- `ProductViewer3D`: обернуть в `React.lazy()` + `Suspense` с skeleton-fallback
- Скрипт конвертации изображений в WebP через ImageMagick
- Обновить все импорты `.jpg`/`.png` → `.webp` в `products.ts`
